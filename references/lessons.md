# Step 9: Log

Record what was learned, in two places, and never change the skill silently.

## In the project

Lessons about *this* project go in the project's own notes (`CLAUDE.md`, `AGENTS.md`, design notes, or a `DESIGN.md`): the direction chosen, the tokens defined, the decisions that were not obvious, the tells that are brand choices and must not be "fixed" later, and what the person liked and disliked. Keep it to a few lines per run. Create the file only if the project already keeps notes of this kind or the person agrees.

## For the skill

General lessons (a tell the list missed, a rule that backfired, a check that would have caught a mistake) are **proposed to the person in chat** with one line of evidence each. Nothing is added to the skill's files until they agree. Never edit the skill's own files during a design run.

## What is worth recording

- The concept (the three lines from `direction.md`) and which ground was chosen and why, so a later run extends the idea instead of replacing it.
- A decision a future run would otherwise reverse (accent colour reserved for live states).
- A surprise (a font that renders wrong on Windows; a component that cannot take a prop).
- A correction from the person, with the reason.
- A check that failed late and could have run early.

## What is not

- A list of what you did (git has it).
- Opinions about the project.
- Anything private or secret.
